Phase 8: Centralized Logging using ELK Stack
Objective

The objective of this phase is to implement a centralized logging solution for the Kubernetes cluster. Instead of accessing logs from individual pods, all application and cluster logs are collected, processed, stored, and visualized from a single platform. This enables efficient monitoring, debugging, and troubleshooting of applications running in Kubernetes.

What is Centralized Logging?

Centralized logging is the process of collecting logs generated by multiple applications, containers, and Kubernetes components into a single location. Since Kubernetes pods are ephemeral and can be recreated at any time, storing logs centrally ensures that historical logs remain available even after a pod is deleted or restarted.

ELK Stack

The ELK Stack is one of the most popular centralized logging solutions and consists of the following components:

Elasticsearch

Elasticsearch is a distributed search and analytics engine that stores and indexes log data. It enables fast searching, filtering, and analysis of large volumes of logs.

Logstash

Logstash is a data processing pipeline that receives logs from various sources, processes and transforms them if required, and forwards them to Elasticsearch for storage.

Filebeat

Filebeat is a lightweight log shipper that continuously monitors log files generated by Kubernetes containers and sends them to Logstash for processing.

Kibana

Kibana is the visualization interface for Elasticsearch. It allows users to search logs, create dashboards, visualize trends, and analyze application behavior through an intuitive web interface.

Working of ELK Stack
Applications running inside Kubernetes generate logs.
Filebeat continuously monitors container log files and collects the logs.
Filebeat forwards the collected logs to Logstash.
Logstash processes and formats the logs before sending them to Elasticsearch.
Elasticsearch stores and indexes the log data.
Kibana retrieves the indexed logs from Elasticsearch and provides search, filtering, and visualization capabilities.
Advantages
Centralized storage of logs.
Faster troubleshooting and debugging.
Easy searching and filtering of log data.
Real-time monitoring of application behavior.
Historical log retention for analysis.
Improved operational visibility across the Kubernetes cluster.
Scalable logging solution suitable for production environments.
Use Cases
Monitoring application logs.
Debugging application failures.
Investigating pod crashes.
Security auditing.
Performance analysis.
Root cause analysis.
Monitoring Kubernetes workloads from a single interface.
Outcome

By implementing the ELK Stack, all Kubernetes application logs are collected, processed, stored, and visualized from a centralized platform. This eliminates the need to access logs from individual pods and provides a reliable, scalable, and efficient logging solution for monitoring and troubleshooting applications





### command used
# Add Elastic Helm Repository
helm repo add elastic https://helm.elastic.co
helm repo update

# Create Namespace
kubectl create namespace logging

# Install Elasticsearch
helm install elasticsearch elastic/elasticsearch \
-n logging \
--set replicas=1

# Install Logstash
helm install logstash elastic/logstash \
-n logging

# Install Filebeat
helm install filebeat elastic/filebeat \
-n logging

# Install Kibana
helm install kibana elastic/kibana \
-n logging

# Verify Resources
kubectl get pods -n logging
kubectl get svc -n logging

# Port Forward Kibana
kubectl port-forward svc/kibana-kibana 5601:5601 -n logging
